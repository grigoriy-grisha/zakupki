## Контекст: что не так сейчас

После прошлого фикса шаблонных меток `{{цены}}` / `{{фасовка поставщика}}` осталась главная дыра: **`applyPostTemplate` живёт только в браузере** (форма `purchase-product-edit-form.tsx:369`), а BullMQ worker читает `item.description` верба-тимно. Поэтому:

- **Сценарий A (поменял товар)** — работает только через сохранение формы (`updateItemProduct` → `emitPurchaseItemChanged` → `ITEM_CHANGED` → `editItemPost`). Кнопка «Опубликовать в TG» в таблице шлёт `POST_CREATE`, который для уже опубликованных товаров — **no-op** (`createPost` выходит при `item.tgMessageId`).
- **Сценарий Б (поменял шаблон в Settings)** — **вообще никак** не доходит до уже опубликованных постов. Нет ни серверной регенерации, ни bulk-операции.
- Дополнительно: при открытии существующего товара в форме `preserveSavedDescriptionRef` short-circuit намеренно блокирует авто-применение шаблона (чтобы не затирать ручные правки) — пользователь должен вручную переключить шаблон туда-обратно.

Решение: **серверная регенерация описания из шаблона**, per-товар кнопка «Обновить пост в TG».

## ЧАСТЬ 2: Серверный сервис регенерации

**Новый файл**: `apps/frontend/src/server/services/purchase-item-description.service.ts`

```ts
export class PurchaseItemDescriptionService {
    constructor(
        private repo: PurchaseRepository,
        private attributeTypeRepo: AttributeTypeRepository,
        private characteristicRepo: CharacteristicRepository,
        private productAttributeRepo: ProductAttributeRepository,
        private currencyRepo: CurrencyRepository,
        private postTemplateRepo: PostTemplateRepository,
        private pricingSettings: PricingSettingsService,
        private eventBus: EventBus,
    ) {}

    /**
     * Перегенерирует PurchaseItem.description из указанного шаблона с актуальными
     * данными товара и сохраняет в БД. Триггерит ITEM_CHANGED — worker обновит пост.
     * templateId === null → описание очищается (как при «Без шаблона»).

        // 1. Загрузить purchase с items (getById уже тянет product+productInclude,
        //    supplier, currency, purchase.currencyRates). Найти item по id.
        // 2. Параллельно загрузить: attributeTypes, characteristics, productAttributes
        //    (это { attributes, characteristics } для productToDescriptionFields).
        // 3. buildShowInTitleByTypeId(attributeTypes) → showInTitleByTypeId.
        // 4. productToDescriptionFields(item.product, showInTitleByTypeId,
        //    attributeTypes, catalog) → базовые DescriptionFields.
        // 5. Дополнить DescriptionFields: name, purchaseTag, supplierName,
        //    currencyName, packAmount/packUnit, pricePerPackCurrency,
        //    minPackageAmount/Unit, supplierLimit/Unit.
        // 6. unitPriceRub = computeUnitPriceRub(packPriceWithOrgFee, packAmount)
        //    где packPriceWithOrgFee = computePackPriceWithOrgFeeRub(...) из
        //    @zakupki/types + rates (из purchase.currencyRates) + orgFeeDefaultPercent.
        // 7. Если templateId !== null:
        //      const tpl = await postTemplateRepo.findById(templateId);
        //      description = applyPostTemplate(tpl.body, fields);
        //    иначе description = ''.
        // 8. await repo.updatePurchaseItem(purchaseItemId, { description });
        // 9. await eventBus.emitPurchaseItemChanged(purchaseItemId);
    }
}
```

**Примечание**: используем `computeUnitPriceRub` / `computePackPriceRub` / `resolveCurrencyRate` / `resolveOrgFeePercent` напрямую из `@zakupki/types` (как уже делает `PurchaseService.recalculateAmounts` в `purchase.service.ts:243-277`). Не тянем клиентский `items-table-pricing.ts` на сервер.

## Не в скоупе

- Bulk-операция «Обновить все посты по шаблону X» — пользователь явно сказал «разово per-товар». Архитектура (серверный сервис + event bus) готова к будущему bulk — надо будет только добавить процедуру с циклом.
- Полное избавление от клиентского `applyPostTemplate` в форме (форма останется live-preview через barrel; регенерация на сервере — отдельный путь для опубликованных постов).
- Миграция БД для сохранения `postTemplateId` на `PurchaseItem` — не нужна: серверный `regenerateDescription` принимает `templateId` параметром, и пользователь сам выбирает шаблон в диалоге при каждом обновлении.
